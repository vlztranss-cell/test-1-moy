# Kling 2.5 vs Sora vs Runway Gen-3: production-опыт после 600+ генераций оживления фото

Весной 2026 года я собрал небольшой сервис для оживления фотографий через video-AI. За первые недели работы через пайплайн прошло больше 600 генераций, и накопилась честная production-статистика по трём ведущим моделям. Хочу поделиться не маркетинговыми бенчмарками, а тем, что реально болело в проде: цены, латентность, content-policy и технические грабли, о которых не пишут в туториалах. Плюс — честная юнит-экономика, включая то, почему сервис пока убыточен.

## Почему Kling, а не Sora или Runway

Sora и Runway недоступны напрямую из России. Технически можно ходить через VPN и зарубежную карту, но на практике это нестабильно и заметно дороже за единицу генерации. По моим прикидкам выходило в 5-10 раз дороже на одно видео, плюс регулярные обрывы и отказы оплаты.

Kling 2.5 от Kuaishou доступен через агрегатор PiAPI, оплата проходит с обычной карты, а латентность держится в районе 30-60 секунд на 5-секундное видео 1080p в вертикали 9:16. Для B2C-проекта с массовой аудиторией это оказалось решающим фактором.

## Сравнение по 600+ генерациям

Ниже — цифры, которые я собрал сам по реальным генерациям. Оценки качества субъективные, по 10-балльной шкале, но основаны на просмотре сотен роликов. Цена Kling — **фактическая**, выведенная из биллинга PiAPI (об этом ниже).

| Метрика | Kling 2.5 | Sora (через прокси) | Runway Gen-3 |
|---|---|---|---|
| Цена за 5с 1080p | **$0.16** | $0.50–1.00 | ~$0.40 |
| Латентность | 30–60с | 90–180с | 60–120с |
| Качество лиц | **9/10** | 9.5/10 | 8/10 |
| Реалистичность движений | 8.5/10 | **10/10** | 7/10 |
| Доступ из РФ | **да** | нет | нет |
| Строгость content-policy | высокая | очень высокая | средняя |
| Отказ на «обычных» фото | ~10–15% | ~5% | ~3% |

**Откуда взялись $0.16.** PiAPI считает расход во внутренних «поинтах». Одна Kling-генерация (5с, std, 1080p, 9:16) списывает ровно **2 000 000 поинтов**. Сопоставив суммарный `point_used` из кошелька с суммой реальных пополнений, я вывел курс ~**12,5 млн поинтов = $1**, то есть **2 000 000 поинтов = $0.16 за видео**. Это важная деталь: в туториалах цену называют то $0.10, то $0.20 — реальная для моего конфига вышла $0.16.

**Вывод:** для российского B2C с массовой аудиторией Kling 2.5 — единственный реалистичный вариант. На «эмоциональных» сценариях (моргание, лёгкий поворот головы, улыбка) он не уступает Sora; Sora и Runway выигрывают на сложной динамике (танец, бег), но проигрывают по цене и доступу.

## Архитектура пайплайна

```
[Юзер на лендинге]
    ↓ загружает фото
[n8n: webhook генерации]
    ↓ файл на бесплатный CDN
[PiAPI Kling 2.5]
    ↓ task_id (асинхронно)
[Polling статуса каждые 5 сек]
    ↓ ready
[Скачивание MP4]
    ↓ ffmpeg overlay watermark + Pillow text PNG
[Caddy proxy /videos/]
    ↓
[Юзер смотрит / скачивает после оплаты]
```

Весь бэкенд — на n8n (workflows как код), PostgreSQL и Docker на одном VPS. Оплата — ЮKassa с чеком по 54-ФЗ. Дальше — про грабли, которые я собрал в проде.

## Грабли №1: Kling отвергает ~каждое 8-е фото

Через несколько дней продакшена я столкнулся с тем, что часть фото отклоняется китайским upstream-сервером Kling с ошибкой вида:

```
图片上传被上游拒绝，请检查图片内容或格式后更换素材重试
```

Что отклоняет (по моим тестам):

- логотипы и торговые марки (даже на фоне);
- лица публичных людей (актёры, политики, в т.ч. российские);
- контент 18+ (даже намёки);
- очень тёмные или низкокачественные фото;
- иногда — пожилые лица с морщинами (false-positive).

Решение: предупреждать пользователя в UI, что подходит, а что нет, и **автоматически возвращать кредит** при отказе. Без авто-возврата это прямой путь к негативу и возвратам.

## Грабли №2: ffmpeg static без drawtext

Я использую статическую сборку ffmpeg (johnvansickle) — в ней **нет фильтра drawtext**, текст нативно не отрендерить. Решение: текст рендерит Pillow в прозрачный PNG, а ffmpeg делает overlay:

```python
# Pillow: прозрачный PNG с текстом
img = Image.new("RGBA", (box_w, box_h), bg_color)
draw = ImageDraw.Draw(img)
draw.text(..., font=ImageFont.truetype(FONT_BOLD, 64))
img.save(out_path)

# ffmpeg: overlay PNG на видео
subprocess.run([
    "ffmpeg", "-i", source, "-i", text_png,
    "-filter_complex", "[0][1]overlay=(W-w)/2:H-h-280",
    output,
])
```

Это даёт полный контроль над типографикой (шрифт, цвет, скруглённые плашки) без пересборок ffmpeg.

## Грабли №3: Cloudflare блочит Python-urllib

`api.piapi.ai` и хранилище отдают HTTP 403 на Python-urllib User-Agent (ботозащита Cloudflare). Лечится подменой UA на browser-like:

```python
req = urllib.request.Request(url, headers={
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) ...",
})
```

curl при этом проходит без проблем — это специфика их WAF-правила именно для Python-Requests.

## Грабли №4: оплата. Никогда не доверяй входящему вебхуку

Самые дорогие грабли — не в нейросети, а в платежах. Мой callback от ЮKassa начислял кредиты по входящему событию `payment.succeeded`, **не перепроверяя реальный статус платежа**. Последствия:

- поддельное/повторное/реверснутое событие с реальным `payment_id` начисляло кредиты на платёж, который по факту был **отменён** (`canceled`);
- на фронте «оплата прошла» показывалась по флагу `is_paid` из **моей же** БД — а он матчил старый чужой заказ по `email ИЛИ session_id`, и пользователь видел «зачислено» после нажатия «Назад» в окне оплаты, ничего не заплатив.

Денег это не теряло (на сервере кредит реально не начислялся), но создавало ложную картину и могло привести к выдаче платных генераций «на доверии».

Что сделал:

1. **Callback перепроверяет статус через API** перед начислением:

```
Webhook → IF event == payment.succeeded
        → GET /v3/payments/{id}        ← перепроверка у источника
        → IF response.status == succeeded
        → начислить кредиты
```

2. **Фронт больше не верит своему флагу.** «Зачислено N» показывается только если **реально вырос баланс** `paid_credits` на сервере (сравниваю его до и после оплаты), а сам баланс наращивает только callback, прошедший проверку через API.

**Мораль:** входящий вебхук платёжки — это уведомление, а не истина. Всегда перепроверяй статус через `GET /payments/{id}` у провайдера. И не используй свой собственный флаг `is_paid` как источник правды.

## Грабли №5: аналитика врала вдвое

Выручку я считал по `is_paid` в своей таблице — и дашборд показывал ~₽10 000. А в кабинете ЮKassa за то же время было ~**₽7 500**. Разница — те самые ложные `is_paid='yes'` на отменённых платежах плюс бесплатные триал-заказы, помеченные «активными».

Пришлось перестроить учёт:

- **выручка** — из зеркала всех платежей, синхронизированного из API ЮKassa (единственный источник правды, считаем только `succeeded`);
- **COGS** — из кошелька PiAPI (`point_used` → доллары по выведенному курсу), а не по оценке «число генераций × прайс».

Мораль: считай деньги по данным провайдера, а не по флагам в своей БД. Иначе принимаешь решения на цифрах, завышенных вдвое.

## Честная юнит-экономика

Без приукрашивания, по реальным данным за первые недели:

- **Выручка** — несколько тысяч рублей (десятки успешных платежей).
- **Расход на генерацию** оказался **выше выручки**.
- Плюс расходы на рекламу сверху.
- **Итог: бизнес пока убыточен.**
- **Конверсия** «ввёл email → оплатил» — около **4–5%**.

Ключевая проблема видна сразу: **бесплатная генерация стоит примерно столько же, сколько приносит средний пользователь.** При марже около нуля реклама (с хорошим CTR, но без окупаемости) просто углубляет минус — поэтому я её выключил и перешёл на органику/крауд-маркетинг.

И главный вывод проекта: **узкое место — не в технологии, а в воронке и юнит-экономике.** Kling 2.5 своё дело делает; деньги теряются на конверсии лендинга и на стоимости бесплатного «вау».

## Что бы я сделал иначе

1. **Сначала считать юнит-экономику, потом лить трафик.** Я выяснил, что воронка убыточна, уже потратив на рекламу — это надо было моделировать заранее.
2. **С первого дня — учёт денег по API провайдеров,** а не по своим флагам. Полнедели я смотрел на завышенную вдвое выручку.
3. **Перепроверять платежи через API сразу,** а не после того, как всплывут «зачисления» без оплаты.
4. **Удешевлять бесплатный тизер** (короче/ниже разрешение), раз он съедает всю маржу.

## Заключение

Kling 2.5 + PiAPI — рабочее production-сочетание для русского B2C на оживлении фото: дешевле и доступнее Sora/Runway, качества хватает для эмоциональной ниши. Но если будете строить такое — закладывайте, что 80% боли будет не в нейросети, а в платежах, учёте и конверсии. Технология сегодня — самая простая часть.

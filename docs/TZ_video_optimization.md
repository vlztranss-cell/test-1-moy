# ТЗ: оптимизация видео лендинга botisk.ru

**Кому:** агент-исполнитель (performance-optimization / claude).
**Зачем:** на главной (`index.html`) 6 фоновых роликов суммарно весят ~23 МБ.
HTML уже переведён на ленивую загрузку с постерами — осталось пережать сами
файлы и сгенерировать постеры. Логику разметки НЕ трогать.

## Контекст (что уже сделано в HTML — не ломать)
- У каждого `<video>` стоит: `preload="none"`, `class="lazy-video"`, `data-lazy`,
  `poster="videos/posters/<name>.webp"`, а у `<source>` — `data-src` вместо `src`.
- JS (`IntersectionObserver`) подгружает ролик и запускает `play()` при подъезде
  к экрану; `autoplay` снят намеренно — воспроизведением управляет скрипт.
- Поэтому: **звук не нужен** (ролики `muted`), **постеры обязательны** —
  именно их видит пользователь до подгрузки видео.

## Вход
Папка `videos/`:
| Файл | Текущий вес | Где на странице |
|------|-------------|-----------------|
| `welcome.mp4` | 3.9 МБ | hero, вертикальный 9:16, показ ~360px |
| `warm_memory.mp4` | 1.6 МБ | карточка примера, object-fit: cover |
| `childhood.mp4` | 3.2 МБ | карточка примера |
| `pet.mp4` | 5.4 МБ | карточка примера |
| `love_story.mp4` | 4.0 МБ | карточка примера |
| `examples.mp4` | 5.5 МБ | карточка примера |

## Задача
### 1. Пережать каждый mp4 (H.264, без звука, faststart)
```bash
ffmpeg -i videos/<name>.mp4 -an \
  -vf "scale='min(720,iw)':-2" \
  -c:v libx264 -profile:v high -pix_fmt yuv420p \
  -crf 30 -preset slow -movflags +faststart \
  videos/<name>.opt.mp4
```
- `-an` — выкинуть аудиодорожку (видео немые).
- `-crf 30` — старт; если визуально замылено, опускать к 26–28, если вес
  большой — поднимать к 32. Подбирать по каждому ролику.
- `scale='min(720,iw)':-2` — не апскейлить, ограничить ширину 720px (показ мелкий).
- После проверки заменить оригинал: `videos/<name>.opt.mp4` → `videos/<name>.mp4`.

### 2. Сгенерировать постеры (первый кадр → WebP)
Создать папку `videos/posters/` и для каждого ролика:
```bash
ffmpeg -i videos/<name>.mp4 -frames:v 1 \
  -vf "scale='min(720,iw)':-2" \
  -c:v libwebp -quality 72 \
  videos/posters/<name>.webp
```
Имена постеров **строго** совпадают с роликами (HTML уже на них ссылается):
`welcome, warm_memory, childhood, pet, love_story, examples` → `.webp`.

### 3. (опционально, плюс к скорости) WebM/AV1-вариант
Если несложно — добавить второй `<source>` с WebM перед mp4 в `index.html`:
```bash
ffmpeg -i videos/<name>.mp4 -an -c:v libvpx-vp9 -crf 34 -b:v 0 videos/<name>.webm
```
Это уже правка HTML — согласовать перед внесением.

## Критерии приёмки
- [ ] Каждый `videos/*.mp4` ≤ **1.5 МБ**; суммарно `videos/` ≤ **8 МБ** (цель ~5 МБ).
- [ ] Существуют все 6 файлов `videos/posters/<name>.webp`, каждый ≤ 80 КБ,
      пропорции совпадают с роликом, картинка не битая.
- [ ] Визуально качество ролика не деградировало на экране показа (mobile + desktop).
- [ ] Ролики по-прежнему **немые** и проигрываются при скролле к ним
      (проверить на botisk.ru после деплоя: видео стартует, постер виден до старта).
- [ ] HTML-разметку видео не меняли (кроме согласованного п.3).
- [ ] `og-image.png` (419 КБ) — по желанию пережать в WebP/оптимизировать PNG,
      это отдельный мелкий бонус, не блокирует приёмку.

## Замечания
- `ffmpeg` на машине пользователя не установлен — поставить
  (`winget install Gyan.FFmpeg` или `choco install ffmpeg`) перед началом.
- Деплой статики — через GitHub Pages (push в `master`); видео лежат в репо,
  папка `videos/` публикуется (в `_config.yml` не исключена).
